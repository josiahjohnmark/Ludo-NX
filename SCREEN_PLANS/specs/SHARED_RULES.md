# SPEC — Shared rules for every screen build

Read this once per session. It applies to **every** file in `SCREEN_PLANS/screens/`.

---

## 1. Order of authority

1. `UI_BIBLE/LUDO_NX_UI_BIBLE.md` — the rules
2. `UI_BIBLE/tokens.json` — the only allowed values
3. The screen's plan file in `SCREEN_PLANS/screens/`
4. The owner's reference image for that screen
5. Anything older

A screen plan may only override the bible where it carries an explicit `deviations` entry saying the owner approved it. If you find a conflict with no deviation entry: **stop and ask the owner.** Never pick silently.

---

## 2. Preflight — before you build anything

Post this list and wait if anything is missing:

1. **Components** you will use, quoted as bible numbers (`5.4 NX Card`, `5.8 Buttons`, ...).
2. **Tokens** you will read from `tokens.json`. If you need a value that is not in there, stop and propose it — do not invent one.
3. **Assets** that do not exist yet, with the exact path they should land at and the image prompt from bible section 8 plus the asset prompt.
4. **Anything in the plan you think is wrong.** Say it in one or two lines, then build it as written unless the owner changes it.

---

## 3. How screens are built in this project

- Screens are **prefabs** under `Assets/Resources/UI/Screens/` (hubs, takeovers) and `Assets/Resources/UI/Modals/` (popups), generated by **editor scripts** in `Assets/Scripts/Editor/`.
- **Never hand-place UI in the scene.** ScreenManager's canvas draws over it and it never reaches a build.
- Every screen gets a test entry under the Unity menu `Ludo NX/UI/Screen Test/`.
- The Unity Editor exposes an MCP bridge at `http://127.0.0.1:8080/mcp` — use it to run the builder and take captures instead of asking the owner to click.
- Colours come from `UITheme` / `tokens.json`. Components never hard-code a colour.
- Text uses the TMP presets in bible 2.3, never a one-off material.

---

## 4. Frame and units

- Design frame **440 x 956 pt**. Every number in a plan file is in this frame.
- Unity canvas is 1080 wide, so **1 pt = 2.4545 units**.
- Bitmaps export **at 3x**. Never upscale 1x art.
- Safe area: top content starts at the device inset, never less than 45 pt.
- Scale uniformly. Plates widen only through the 9-slice middle. Never stretch on one axis.

---

## 5. Linear colour space

This project renders in Linear, so semi-transparent layers authored in Figma come out lighter. Pre-blend anything sitting on a known colour into an opaque sprite. For an alpha over a changing background, correct it: `raw = 1 - (1 - perceived)^2.2`. Verify by sampling a flat area of a play-mode capture against the reference.

---

## 6. Honesty rules (project law, not style)

- Never label a mode "online" and never claim a real player was found, until real online play ships.
- Bots are always labelled **BOT**, visibly, on the seat and on the result row.
- Never show invented "global" players in rankings as if they were real.
- Real-money prices come from the RevenueCat offering as the store's localised string. Never a hard-coded dollar amount in production.

---

## 7. Postflight — how to report a finished screen

1. The **Definition of Done** checklist from bible section 11, every line ticked or explained.
2. The plan file's own `acceptance` list, every line ticked or explained.
3. Captures at **1080 x 2400**, one per state listed in the plan.
4. The files you changed.
5. Update `SCREEN_PLANS/index.json`: set that screen's `status`, and add today's date to `last_touched`.
6. Update `AI_HANDOFF.md`: tick the task, add a LOG line, clear NOW. Gemini ticks as `[x] (review)`.

---

## 8. Never

- Never change `LUDO_NX_UI_BIBLE.md`, `tokens.json` or the architecture in `GO_LIVE_PLAN.md`. Write it under PROPOSALS in `AI_HANDOFF.md` instead.
- Never invent a colour, font, size, radius, shadow or timing.
- Never bake text into an image. Logotypes are the only exception (bible 2.8).
- Never put more than one red `play` button on a screen.
- Never ask for or paste passwords, keystore passwords, service-account files or private keys.
- Never commit to git unless DECISIONS in `AI_HANDOFF.md` says the owner allowed it.
